# Spec：問答 Agent 外掛（RSForm 評估、真人客服轉接）

> 狀態：v1.3；第 1、2 階段已完成（Ask the Site 0.8.0，2026-10-15），第 3 階段已完成（0.9.0，2026-10-16；後台批次產生圖庫尚未做，結果類型的代表圖目前由媒體庫選取），第 4 階段已完成（0.10.0，2026-10-16；用 LiveChat 小工具的留言表單，尚未接 HelpDesk API）。適用：官網內容問答（pkg_mcpask）0.8 起。
> 決定事項見第 12 節。

## 1. 目標

讓問答平台可以掛上「Agent」：特定問句、開窗推薦或訪客行為會觸發一個專門的小幫手，接手對話完成某件事。

第一批兩個：
1. **RSForm 評估 Agent**：用對話填寫網站既有的 RSForm 表單，再依答案與網站特定分類的內容，產生一份長篇、分段、有插圖的分析報告（類似心理測驗結果）。
2. **LiveChat 真人客服 Agent**：在問答視窗中轉接真人客服；下班或無人在線時改為留言，轉進 LiveChat 的工單（HelpDesk），並在後台留下轉接紀錄。

之後可以再擴充其他 Agent，也可以把真人客服改成內建功能（第 11 節）。

## 2. 設計原則

1. **Agent = Joomla 外掛**（群組 `mcpask`），用一般的 Joomla 安裝包安裝、更新、移除；不另外做「上傳 MCP Server／Skill」的安裝包（理由見第 3 節）。
2. **AI 不產生 HTML**：表單、報告、按鈕都由前端依結構化資料（JSON）畫出，維持 0.6.5 起的防注入原則；所有文字經過同一套輸出過濾。
3. **伺服器端掌握狀態**：進行到哪一步、已填了什麼都存在伺服器端，不信任瀏覽器傳來的狀態。
4. **送出前一定確認**：任何會送出資料、建立紀錄的動作，都先讓訪客看過摘要並確認。
5. **可設定、可預覽**：每個 Agent 的觸發方式、指示樣板、畫面文字與動畫、報告結構都在後台設定，並可在「外觀」頁的預覽中試跑。

## 3. 為什麼用 Joomla 外掛，而不是 MCP／Skill 安裝包

| 考量 | 說明 |
|---|---|
| MCP | MCP 是讓外部 AI 用戶端（例如 Claude）呼叫網站工具的協定；問答的 Agent 在網站內執行，直接呼叫 PHP 即可。一般 Joomla 主機也無法常駐 MCP 程序。 |
| Skill | Claude 專用格式；背後用 GPT／Open WebUI 時，對應的是「指示樣板＋工具定義（function calling）」，用文字在後台編輯。 |
| 安全 | 上傳可執行的程式包等於開放任意程式執行；Joomla 安裝程式已有安裝、更新、權限與簽章機制。 |
| 對外（給 Claude） | 每個 Agent 的後台資料（填單紀錄、轉接紀錄）透過現有 MCP Server 的擴充工具提供，做法同操作教學的審核工具。 |
| 對內（呼叫外部系統） | 之後若要接 BizForm 等外部 MCP Server，做成一種「遠端工具」Agent：只設定網址、金鑰與允許的工具清單，由伺服器端呼叫，不上傳程式。 |

## 4. 架構

### 4.1 Agent 外掛介面

外掛類別實作 `AgentInterface`（放在 com_mcpask），宣告：

| 項目 | 內容 |
|---|---|
| `type()` | 類型代碼，例如 `rsform`、`livechat` |
| `requires()` | 需要的元件，例如 `com_rsform`；沒有安裝就不出現在「新增 Agent」清單 |
| `form()` | 這個類型專屬的設定欄位（Joomla Form XML） |
| `defaults()` | 預設的觸發方式、指示樣板、畫面文字 |
| `start(Session)` | 接手對話時的第一步 |
| `handle(Session, Input)` | 處理訪客的每一次輸入（文字、填寫的欄位、按下的按鈕），回傳下一步要畫的東西 |
| `tools()` | 提供給 AI 呼叫的工具（function calling 的定義與 PHP 實作） |

### 4.2 Agent 管理頁（官網內容問答 → Agents）

- 列表：名稱、類型、狀態、觸發方式、最近 30 天觸發／完成次數。
- 新增：選類型（只列出已安裝、已啟用、所需元件存在的外掛）→ 填設定；同一類型可以建立多個實例（例如兩張不同表單）。
- 每個 Agent 共用的設定：
  - 名稱、頭像（可用小寵物）、開場白
  - 適用範圍：頁面（選單項目）、語言、使用者群組
  - 觸發方式（第 5 節）
  - 指示樣板（給 AI 的規則，文字可編輯）
  - 知識範圍：可以引用的分類、標籤（只拿這些內容給 AI 組合）
  - 畫面文字與動畫：每個處理階段顯示的文字（例如「正在分析你的回答…」「正在挑選適合的方案…」）與小寵物動作
  - 次數限制：每位訪客每天幾次（沿用問答的限制機制）
- 權限：新增、編輯 Agent 需要「選項」權限。

### 4.3 對話接手

- Agent 啟動時，對話中出現一張「已切換到〔數位轉型評估小幫手〕」的卡片，頂部顯示目前的 Agent 與「離開」按鈕。
- 對話紀錄（`#__mcpask_agent_sessions`）：Agent、訪客（雜湊）、狀態、目前步驟、已收集的欄位（加密保存，完成或 24 小時後清除）、開始與完成時間。
- 離開或完成後，回到一般問答。

### 4.4 卡片種類（前端依 JSON 畫出）

| 卡片 | 用途 |
|---|---|
| `fields` | 一組欄位：文字、Email、下拉、單選、多選、日期、多行文字；含必填、驗證訊息、預設值 |
| `suggestions` | 推薦問句按鈕；點了先放進輸入框，訪客可以修改再送出 |
| `summary` | 確認摘要：列出所有已填內容，可回頭修改，按「確認送出」才送出 |
| `progress` | 處理中：階段文字＋動畫（點點、小寵物動作） |
| `report` | 分析報告（第 6 節） |
| `handoff` | 真人客服：在線／離線狀態、轉接按鈕、留言 |

## 5. 觸發方式

可以同時設定多種：

1. **開窗推薦**：打開問答視窗時出現推薦問句，例如「幫我評估需要哪些數位轉型工具」。
2. **問句相近**：訪客的問題和設定的觸發問句語意相近時（沿用「指定來源規則」的向量比對，門檻可調），先回答問題，再詢問要不要開始。
3. **AI 判斷**：把 Agent 當成一個工具交給問答的 AI，由它判斷這個問題是否適合交給 Agent（例如在比較方案、問適合哪個產品）。
4. **訪客行為**（主動彈出，由小寵物或浮動按鈕旁的泡泡顯示）：
   - 新訪客（第一次來）
   - 在網站停留超過 N 秒，或看了某分類 N 頁
   - 回訪第 N 次
   - 指定頁面（例如方案比較頁）
   - 頻率限制：同一位訪客 N 天內最多出現一次，關閉後以 cookie 記住。

## 6. RSForm 評估 Agent

### 6.1 讀取表單

依 RSForm 的資料表（`#__rsform_components`、`#__rsform_properties`）讀出欄位：

| RSForm 欄位 | 對話中 |
|---|---|
| `textBox`、`textArea` | 文字欄位（Email 規則 → Email 欄位） |
| `selectList`、`radioGroup`、`checkboxGroup` | 下拉、單選、多選；選項格式 `值\|標籤`、`[c]` 為預設勾選 |
| `calendar` | 日期 |
| `freeText` | 說明文字，照樣顯示 |
| `hidden` | 不顯示，依設定帶入（例如來源頁面） |
| `pageBreak` | 分頁：一頁式表單一次給整張卡片，分頁式一次給一頁 |
| `captcha`、`recaptcha`、`hcaptcha` | 不顯示，改由問答的頻率限制與防濫用機制把關（已確認） |
| `submitButton` | 不顯示，改為確認摘要的「確認送出」 |

### 6.2 填寫流程

1. 開場：說明會問哪些問題、大約幾分鐘、資料用途（連結隱私權政策）。
2. 逐頁給欄位卡片；訪客也可以直接打一段話回答，AI 把內容抽取到對應欄位（工具 `fill_fields`），只追問缺少或不合格的必填欄位。
3. 每頁完成後，依下一頁的欄位產生 2～3 個推薦問句（工具 `suggest_questions`），訪客可以修改再送出。
4. 全部完成 → 確認摘要 → 訪客按「確認送出」。
5. 透過 RSForm 自己的送出流程寫入（保留 RSForm 的通知信、送出紀錄、其他整合）；驗證規則（必填、Email 等）在伺服器端再檢查一次。
6. 送出後產生分析報告（6.3）。

### 6.3 分析報告（像心理測驗的結果）

報告結構在後台定義，**AI 依結構產生 JSON，前端畫成一份有設計感的報告**，而不是一段簡短的回答。

後台的「報告結構」：
- 報告標題樣板（例如「你的數位轉型類型：{type}」）
- **結果類型**（選填）：預先定義幾種類型，例如「起步探索型」「流程整合型」「數據驅動型」，各有名稱、一句話描述、代表色、代表圖；AI 依答案判斷屬於哪一型
- **評分維度**（選填）：例如「流程數位化」「資料整合」「協作效率」0–100 分，畫成長條或雷達圖
- **段落**：依序定義，每段有：
  - 標題
  - 這一段要寫什麼（給 AI 的說明，例如「依剛剛的回答，分析目前的工作方式與痛點，說明原因」）
  - 字數範圍（例如 300–500 字）
  - 插圖方式：無／圖庫／即時產生（6.4）
  - 是否要列出推薦方案（從知識範圍的分類挑選，附來源連結）
- 結尾：行動按鈕（例如「預約顧問」「下載方案說明」「轉接真人客服」）

預設範本（可改）：

| 段落 | 內容 | 插圖 |
|---|---|---|
| 你的類型 | 結果類型名稱、一句話描述、評分圖 | 類型代表圖 |
| 你的現況分析 | 依剛剛的回答，分析目前的工作方式、痛點與原因 | 圖庫或即時產生 |
| 適合你的方向 | 建議的做法與優先順序，說明為什麼適合 | 圖庫或即時產生 |
| 推薦方案 | 2–3 個方案，各自說明適合的理由、可以解決的問題，附來源 | — |
| 下一步 | 具體的行動建議＋按鈕 | — |

生成方式：
- 只用知識範圍內的已索引內容（與問答相同的檢索），每段落的事實要能對應來源，經過同一套輸出過濾。
- 段落分開生成並逐段串流顯示（每段有自己的「處理中」文字與動畫），總長度可以到 2,000 字以上，不會等太久才看到第一段。
- 報告可以存成一個不公開網址（有效期限可設），並可以寄到訪客在表單填的 Email。

### 6.4 插圖

| 方式 | 說明 | 成本與速度 |
|---|---|---|
| **圖庫（建議預設）** | 每個結果類型、每個段落事先準備幾張圖；可以在後台用 AI 產生後挑選、核准，也可以上傳自己的圖 | 不另外花費，立即顯示，風格一致、內容可控 |
| **即時產生** | 依訪客答案組成提示詞，呼叫圖像模型：OpenAI（GPT Image 系列）或 Open WebUI 設定的圖像服務，兩者都支援 | 每張約 US$0.01–0.04（中等品質）、10–30 秒；以提示詞雜湊快取，可設每日上限，失敗時改用圖庫 |

圖像服務的設定與呼叫方式沿用支援中心的「AI 生圖」外掛（`plg_system_gssaiimage`）：有安裝時直接沿用它的服務設定與金鑰；沒有時，元件自己存一份同樣的參數——服務（`openai`／`openwebui`）、API 位址、金鑰、圖像模型（OpenAI 預設 `gpt-image-1` 系列、Open WebUI 可留空由伺服器決定）、品質（OpenAI）、比例、輸出格式（webp）、逾時。OpenAI 呼叫 `/images/generations`；Open WebUI 呼叫 `/api/v1/images/generations` 並取回檔案後刪除伺服器上的暫存。

即時產生的提示詞由後台樣板加上抽象化的答案組成（例如公司規模、產業、痛點類別），**不放入訪客的姓名、Email 等個人資料**；圖片存在網站自己的 `images/` 子資料夾。

## 7. LiveChat 真人客服 Agent

### 7.1 設定

- LiveChat 授權號碼（License ID，公開資訊）、群組（Group ID）
- 上班時間（每週時段、時區）與例外日（假日）
- 觸發：對話頂部的「轉接真人客服」按鈕；訪客提到「真人」「客服」等字；連續兩次「沒幫助」；Agent 流程中的按鈕（例如報告結尾）
- 交接內容：要帶給客服的資訊（問題、AI 回答摘要、所在頁面、評估報告連結）

### 7.2 流程

1. 訪客要求轉接 → 判斷是否在線：上班時間內，**且** LiveChat 小工具回報有人在線（`LiveChatWidget.get('state').availability`）。
2. **在線**：載入 LiveChat 小工具（平常不載入，點了才載入），用 `set_session_variables` 帶入交接內容、用 `set_customer_name`／`set_customer_email` 帶入已知的姓名與 Email，再展開小工具；問答視窗收起。
3. **離線**：一樣打開 LiveChat 小工具，由它的「留言」表單建立工單，進入你們的 LiveChat 工單（HelpDesk）。交接內容同樣以 session variables 帶入，客服在工單中可以看到。
4. **紀錄**：監聽小工具的事件（開始對話、送出留言表單），寫入轉接紀錄 `#__mcpask_handoffs`：時間、訪客（雜湊）、在線或離線、是否成功開始對話或送出留言、交接內容摘要、來自哪個 Agent 或問題。
5. 後台「轉接紀錄」列表（含篩選、匯出），並提供 MCP 工具 `list_handoffs`。

> 實作備註（0.10.0）：網站版型本身已經用舊版安裝碼載入 LiveChat 時（gsscloud 的 vital2022 版型即是），不會重複載入，改用頁面上已有的 API（`LC_API` 舊版或 `LiveChatWidget` 新版）開啟視窗、帶入資訊、監聽開始對話與送出留言；此時群組以版型的設定為準。

> 備案：若希望由我們的表單收集留言，再由伺服器端呼叫 HelpDesk API 建立工單，需要 HelpDesk 的 API 權杖；可以列為選項，預設用 LiveChat 小工具的留言表單（不需要金鑰，最穩定）。

### 7.3 注意事項

- LiveChat 小工具會設定自己的 cookie：只在訪客按下轉接後才載入，符合 cookie 同意的做法。
- 交接內容不放密碼、身分證等敏感資料；表單的個人資料只帶姓名與 Email。

## 8. 前端與外觀

- 卡片與報告都使用「外觀」頁的配色變數（0.7.3），報告另有專屬樣式：封面（類型名稱＋代表圖＋評分）、段落卡片（標題、內文、插圖）、推薦方案卡片、行動按鈕。
- 每個處理階段的文字與動畫可以設定；啟用小寵物模式後，對應寵物的動作（思考、回答中、開心）。
- 手機版：卡片全寬、欄位大字，鍵盤不遮住（沿用 0.6.4 的做法）。

## 9. 安全與隱私

- AI 只能透過宣告的工具動作；工具在伺服器端驗證輸入（欄位名稱、選項值、必填、格式）。
- 表單送出、建立紀錄前一定經過訪客確認。
- 收集的欄位在 Agent 對話紀錄中加密保存，完成或 24 小時後清除；長期資料只存在 RSForm 自己的送出紀錄。
- 問答紀錄不存表單內容；轉接紀錄只存交接摘要。
- 觸發與次數限制沿用問答的限制，主動彈出有頻率上限。

## 10. MCP 工具（給 Claude 等 AI 用戶端）

`list_agents`、`agent_stats`（觸發、完成、轉換率）、`list_handoffs`、`list_agent_reports`（報告摘要，不含個人資料）。

## 11. 階段與估計

| 階段 | 內容 | 估計 |
|---|---|---|
| 1 | Agent 框架：外掛介面、Agents 管理頁、對話接手、卡片 UI、伺服器端狀態、觸發（開窗推薦、問句相近、AI 判斷） | 4–5 天 |
| 2 | RSForm Agent：讀表單、一頁式／分頁式、AI 抽取欄位、推薦問句、確認後送出（以兩張範例表單測試） | 3 天 |
| 3 | 分析報告：報告結構設定、分段串流生成、報告樣式、圖庫插圖與後台 AI 產生圖庫、即時產生（含快取與上限）、報告網址與寄信 | 3–4 天 |
| 4 | LiveChat Agent：轉接、上班時間、離線留言轉工單、轉接紀錄＋後台列表＋MCP 工具 | 2 天 |
| 5 | 行為觸發（新訪客、停留時間、回訪）＋小寵物主動彈出（併入小寵物模式） | 1–2 天 |
| 之後 | 內建真人客服（含多語自動翻譯），可取代 LiveChat | 另行規劃 |

## 12. 決定事項（2026-10-15）

1. RSForm 以支援中心的兩張範例表單開發與測試：`RSFormPro example`（一頁式）、`RSFormPro Multipage example`（分頁式）。
2. 對話填單時不使用原表單的驗證碼，改由問答的頻率限制與防濫用機制把關。
3. LiveChat 離線留言轉進 LiveChat 工單（HelpDesk），並在後台留下轉接紀錄。
4. 小寵物模式最後再做；行為觸發的主動彈出併入小寵物模式。
5. 內建真人客服（含多語翻譯）列為之後的項目。
6. 即時產生插圖同時支援 OpenAI 與 Open WebUI，參數與呼叫方式沿用「AI 生圖」外掛（6.4）。
